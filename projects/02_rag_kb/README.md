# RAG 知识库问答：自实现 BM25 检索 + 引用溯源 + 检索评测

把本账号 5 个仓库的 13 篇 README 建成知识库，回答"哪个项目做了假设检验？"
这类问题。两种模式：**纯检索模式**（完全离线）与生成式回答（引用标注）。
这个项目最大的价值不是"搭了个 RAG"，而是**为检索建了评测集并用它迭代**。

## 架构

```
13 篇 README
   │  chunker.py：按 1-4 级标题切块，层级标题路径并入正文
   ▼
81 个带元数据的块 (doc, section, text)
   │  bm25.py：Okapi BM25（jieba 中文分词 + 英文整块）
   ▼
BM25Index.search(question) ──► top-k 片段
   │  ask.py --llm（可选）：组装带编号的上下文 → LLM 生成引用标注的回答
   ▼
回答 + 出处列表
```

## 检索评测：recall@3 从 50% 到 83% 的过程

构造 12 条测试问题（期望命中文档 + 章节关键词），`evaluate.py` 输出
recall@3 / MRR 和未命中归因。两轮真实迭代：

| 版本 | recall@3 | MRR | 改动 |
|---|---|---|---|
| v1 按一级标题粗分块 | 50% | 0.347 | 块太大、标题信号丢失 |
| v2 多级标题切分 + 路径并入正文 | 67% | 0.569 | "LRU"等词命中正文所在章节 |
| v3 + 标题命中加权（×1.25/词） | **83%** | **0.750** | 主题对齐的块提前 |

剩余 2 个未命中的归因（如实保留）：查询词形与目标章节重合度低
（"防止标签泄漏"的目标块用词是"防泄漏对照实验"），BM25 词面匹配的固有局限，
升级方向是语义向量检索。

## 使用

```bash
# 纯检索（离线）
python ask.py "哪个项目做了假设检验？"
python ask.py "怎么防标签泄漏" --top-k 5

# 生成式回答（任意 OpenAI 兼容模型）
export OPENAI_BASE_URL=... OPENAI_API_KEY=... OPENAI_MODEL=...
python ask.py "哪个项目做了假设检验？" --llm

# 检索质量评测
python evaluate.py
```

## 局限

- 语料只有 13 篇文档 81 块——刻意选的小规模，便于评测与归因；
- BM25 无语义泛化能力（"防止X"搜不到"防X对照"）；
- 生成模式未做幻觉评测（引用标注 + 仅依据资料的系统提示是目前的缓解）。
